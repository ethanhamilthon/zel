# 0.11.0: Lua only — design spec

Source of truth for the 0.11.0 work. Breaking release, no migration of old
configs or sessions. Old Lua runtime of 0.6 (commit 39f42d0, `internal/luart`)
is a good base: `git show 39f42d0:internal/luart/vm.go` etc.

## 1. The agent tool

- The model has one tool, `lua` (was `bash`). Input: Lua code (Lua 5.1, gopher-lua
  `github.com/yuin/gopher-lua`). Freeform on Responses with the field `code`,
  JSON `{"code": ...}` elsewhere. History keeps `function_call` `{"code": ...}`.
- One agent VM per session. Globals survive between calls. The VM is reset
  (fresh state) when a call times out, when the config reloads, and when the
  session changes. The next output then starts with `[lua: fresh VM]`.
- A call has `settings.timeout` seconds (default 30), including blocking host
  calls (`sh`, `task.wait`...). Longer work goes to `task.spawn`.
- Output = what the code `print()`s, then the returned values (strings as is,
  tables as JSON, several values one per line). A raised error appends
  `error: <msg>`. Timeout appends `[timeout after 30s; VM reset]`.
  Runtime caps raw output at 1 MiB (head+tail). The core then cuts to
  `settings.output` bytes (default 8000) with the full text in a file (existing
  `cutOutput`).
- Steering during a call: the call runs to its end; calls of the same response
  that have not started are skipped (`[skipped: superseded by steering]`).
- Stdlib fully open (`io`, `os`, ...).

## 2. Agent API (globals in the agent VM and task VMs)

Errors raise `"fn: CODE: msg"` (codes `EINVAL ENOENT ENOMATCH EAMBIG ELIMIT
EFAIL EDENIED ETIMEOUT ECANCELED`), catchable with `pcall`.

```lua
sh(cmd, o?) -> {ok, code, out, timed_out, ms}
  -- bash -c in its own process group, in the session cwd, with the session env
  -- (ZEL_SESSION_ID, ZEL_SOCKET, ZEL_TOKEN, ZEL_CONFIG, ... + settings.env).
  -- out = stdout+stderr. o: timeout (s, capped by the call's time left), cwd,
  -- env {K=V}, stdin, check (raise EFAIL when code ~= 0). Never raises otherwise.
  -- `zel -p` subagents are started with sh("zel -p ...").
read(path) -> string        -- relative to session cwd; > 16 MiB: ELIMIT
read("img.png") -> nil      -- png/jpg/jpeg/gif/webp: attaches the image to the next request
slice(s, from, count?) -> string   -- lines from..from+count-1; from < 0 counts from the end
write(path, s, o?)          -- o.append; parent dirs created
edit(path, old, new, o?) -> n      -- exact text; ENOMATCH; EAMBIG unless o.all
edit(path, {{old, new, all?}, ...}) -> n  -- several edits, all or nothing
list(dir?) -> {name, dir, size}[]
glob(pattern) -> string[]          -- "internal/**/*.go"
grep(re, o?) -> {file, line, text}[]  -- Go RE2, walks o.path (default cwd),
  -- respects .gitignore (root .gitignore and nested ones), skips .git and binary
  -- files. o: path, glob, fixed (literal), max (default 200)
exists(path) -> bool, "file"|"dir"|nil

task.spawn(name, fn, o?) -> id   -- fn runs in its own fresh VM (agent API), no
  -- call timeout; o.timeout (s). fn gets COPIES of its upvalues (data, tables,
  -- functions recursively); globals of the calling VM are not there.
  -- Its print() goes to the task log; return value is the result.
  -- When nobody waits, a notification "<notification>t1 finished: ...</notification>".
task.list() -> {id, name, state, ms}[]
task.get(id) -> {id, name, state, ms, result?, error?} | nil
task.wait(id | {ids}, timeout?) -> result | results[]  -- nil where not finished
task.tail(id, n?) -> string      -- last lines it printed (default 20)
task.stop(id)

choice(question, {options...}) -> id   -- non-blocking picker in the UI; the
  -- answer arrives as a notification. Main session only (headless: EDENIED).
cd(dir?)            -- folder of the next calls; no arg = back to start folder
docs(topic?) -> string
models() -> {provider, model, context_window}[], failures
session.id, session.name, session.cwd, session.root, session.mode ("main"|"headless"),
session.modes (list, with the --mode one), session.depth, session.model,
session.effort, session.provider
session.rename(name)
```

Config functions (section 4) are globals too, called with one table:
`server_sh{cmd = "docker ps"}`. A name that collides with a built-in is a config error.

## 3. VMs

- **agent VM**: one per session, globals above.
- **task VM**: one per `task.spawn`, globals above, its own goroutine.
- **config VM**: one per config snapshot; runs `init.lua`, `zel.lua`, their
  loads; then the bodies of `functions` and sync `hooks`. Serialized by a
  mutex. Here the API is ONLY the module `local zel = require("zel")` with the
  same functions as section 2 under `zel.` (`zel.sh`, `zel.read`,
  `zel.task.spawn`, `zel.session.mode`, ...). No API globals in the config VM.
- **async hook VM**: an async hook runs in a fresh VM with copies of its upvalues
  (like a task), `zel` module style.
- Calls between VMs (agent -> config function) copy arguments and results (data
  only; functions are not passed across, except via task/async-hook upvalue copy).

## 4. Config files

Only three files:

- `~/.config/zel/init.lua` (global; `$ZEL_HOME/init.lua`; `--config FILE` replaces it
  and then `zel.lua` is NOT read),
- `./zel.lua` (local, only in the session's start cwd, no upward search, loaded
  without any trust prompt),
- `~/.config/zel/connect.json` (providers + active selection; `$ZEL_HOME/connect.json`).

Sessions stay in `~/.zel/sessions/`. YAML, `settings.yaml`, `systems/`,
`prompts/`, `hooks/` and `${{ }}` are gone (no yaml dependency).

`init.lua` and `zel.lua` return a table; unknown keys are an error:

```lua
local zel = require("zel")
return {
  settings = {
    compaction = 400000,   -- tokens, 0 = off
    timeout = 30,          -- s per lua call
    output = 8000,         -- bytes of one call the agent gets, 0 = no cut
    show_code = true,      -- working line shows the running code
    show_prompt = false,   -- chat shows the full #prompt text instead of #name
    trace_hooks = true,
    editor = "nvim",
    colors = { accent = "#c3e88d", trace = { lua = "#a0a0a0" } },
    keys = { menu = "ctrl+k" },
    env = { EDITOR = "true" },
  },
  systems = { style = "Reply short.", git = "git: " .. zel.sh("git branch --show-current").out },
  prompts = { review = "Review the diff of the current branch." },
  functions = {
    server_sh = {
      description = "run bash on mainserver. args: cmd. returns like sh()",
      fn = function(a) return zel.sh("ssh mainserver 'bash -s'", {stdin = a.cmd}) end,
    },
  },
  hooks = {
    { events = {"lua_before"}, fn = function(event, data)
        if data.code:find("git push %-%-force") then return false, "no force push" end
      end },
    { events = {"idle"}, async = true, fn = function() zel.sh("osascript -e 'display notification \"done\"'") end },
  },
  loads = { "lua/web.lua" },   -- relative to this file; same shape, but no loads inside
}
```

- `systems`, `prompts`: name -> string (only strings). Names 1..64 of
  `[A-Za-z0-9_-]`. Systems are ordered by file (init, its loads, zel.lua, its
  loads), inside a file by name. Dynamic text is computed at load time with `zel.*`.
- `functions`: name -> `{description, fn}`. `description` goes into the tool
  description (`- name{...}: description`).
- `hooks`: a list of `{events = {...}, fn, async?}`.
- No `modes` anywhere: config code checks `zel.session.mode` / `zel.session.modes`.
- Merge order: init.lua, its loads, zel.lua, its loads. `settings` deep-merged,
  later wins. Same name in prompts/systems/functions: later replaces earlier
  with a warning. Hooks are concatenated in that order.
- Loading runs with a 30 s budget. An error in any file makes the snapshot
  invalid: at start Zel runs with defaults + error notice; on hot reload the
  previous snapshot stays.
- `package.path` gets the folder of each config file (`?.lua`).
- Hot reload watches init.lua, zel.lua, every loaded file, connect.json.

### connect.json

```json
{
  "provider": "openai",
  "model": "gpt-5",
  "effort": "medium",
  "providers": {
    "openai": {"base_url": "https://api.openai.com/v1", "api": "responses", "api_key": "$OPENAI_API_KEY"},
    "local": {"base_url": "http://localhost:11434/v1", "api": "chat", "api_key": ""}
  }
}
```

- Any string value that is exactly `$NAME` or contains `$NAME`/`${NAME}` is
  expanded from the process env; `$$` is a literal `$`.
- The model menu writes `provider`, `model`, `effort` back (rest kept, pretty JSON).
- No `modes` on providers.

## 5. Hooks

`fn(event, data)` runs in the config VM (sync) or a fresh VM (async), 60 s each.
Return values replace exit codes / stdout:

- `nil` (or nothing): no effect.
- a string: the "stdout" of the old hooks (replacement text / notification /
  appended output, per event).
- `false, "reason"`: blocks a blockable event (old exit 2).
- a raised error: logged in Tracing and diagnostics, the hook is skipped.

Async hooks: return values ignored.

| event | data | string return | `false, reason` |
|---|---|---|---|
| `session_created` / `session_resumed` | `{}` | | |
| `session_closed` | `{reason}` | | |
| `config_changed` | `{ok, error, file}` | | |
| `message` | `{text}` | new text | message dropped |
| `notification` | `{text}` | new text | dropped |
| `turn_start` | `{text}` | | |
| `turn_end` | `{answer, running = {{id, name, ms}}}` | notification, turn goes on (max 3) | |
| `idle` | `{}` | | |
| `lua_before` | `{code}` | replaces the code | not run, agent sees `[blocked by a hook: reason]` |
| `lua_after` | `{code, out, ok, ms, timed_out}` | appended to the output | |
| `compaction` | `{before, after}` | | |
| `model_changed` | `{provider, model, effort}` | | |
| `error` | `{kind, message}` | | |

## 6. Prompts

- `#name` in the composer expands to `<prompt name="name">\nTEXT\n</prompt>`
  (was `<completion ...>`). Unknown names stay as typed. Text is a plain string
  now (no expansion step, no timeout).
- `settings.show_prompt` (default `false`): the chat renders each
  `<prompt name="x">…</prompt>` block of a user message as `#x` (the history
  keeps the full text; works for resumed sessions; a change applies at once).
  `true` shows the full text. Tracing always shows the full text.

## 7. CLI and socket

- Removed subcommands: `zel task`, `zel choice`, `zel view`, `zel edit`,
  `zel cd`, `zel session`. Kept: `zel`, `zel -p`, `zel version`, `zel help`,
  `zel update`, `zel docs [TOPIC]`, `zel models`, `zel config`.
- The session socket stays only for `zel -p` children (`child.start`,
  `child.end`, `child.usage`). A child takes the parent's init.lua from
  `ZEL_CONFIG` and reads `zel.lua` of its own cwd unless the parent ran with
  `--config` (`ZEL_NO_LOCAL=1`).

## 8. UI renames

- Settings: `bash_timeout` -> `timeout`, `bash_output` -> `output`,
  `show_bash` -> `show_code` (Go: `Timeout`, `Output`, `ShowCode`, `ShowPrompt`).
- Tracing: kind `bash` -> `lua`, tab `Bash` -> `Lua`, Lua syntax highlighting,
  color `trace.bash` -> `trace.lua`.
- Turn summary / working line counter `bashs` -> `calls`.
- Working line: the running Lua code (first lines), like bash before.

## 9. Package contracts (Go)

Dependency graph: `config` (no internal deps), `luart` imports `config`,
`shell`, `edit`, `docs`; `core` imports `luart`. `luart` never imports `core`.

### config (workstream B)

```go
type Settings struct {
    Provider, Model, Effort string
    CompactionThreshold     int
    Timeout, Output         int   // s per lua call; bytes, 0 = no cut
    ShowCode, ShowPrompt    bool
    TraceHooks              bool
    Editor                  string
    Colors                  Colors
    Keys                    map[string]string
    Env                     map[string]string

type System struct{ Name, Text string }

type Config struct {
```

### luart (workstream A)

```go
type Env interface {
    Info() SessionInfo       // ID, Name, Cwd (current), Root, Mode, Modes, Depth, Model, Effort, Provider, TmpDir
    ShellEnv() []string      // KEY=VALUE for sh()

    Attach(path string) error                       // image for the next request
    Choice(question string, options []string) (string, error)
    Rename(name string) error
    Models(ctx context.Context) ([]ModelInfo, map[string]string)
    Tasks() Tasks            // registry owned by core
    Log(kind, msg string)    // Tracing / diagnostics
}
type TaskFunc func(ctx context.Context, out io.Writer) (result string, err error)
type Tasks interface {
    Spawn(name string, timeout time.Duration, run TaskFunc) (id string, err error)
    List() []TaskInfo
    Get(id string) (TaskInfo, bool)

// Config VM
func LoadConfig(ctx context.Context, env Env, paths config.Paths, base config.Settings) (*Config, error)

func (c *Config) RunHook(ctx context.Context, h config.Hook, event string, data map[string]any) (HookResult, error)
    // HookResult{Text string; HasText bool; Blocked bool; Reason string}; async hooks: started in fresh VM, returns at once
func (c *Config) Close()

// Agent VM
func NewAgent(env Env, cfg *Config) *Agent   // cfg may be nil (no functions)

func ToolDescription(t ToolText) string  // ToolText{Headless, Nest, Timeout, Functions}
    // the tool text, from the embedded lua_main.md with [main]/[headless]/[nest] lines
```

## 10. Workstreams (parallel branches, integration later)

Each workstream touches only its files; `core` integration (bash tool ->
lua tool, hooks, tasks registry, socket trim, children) is done afterwards by
the integrator. Your branch must pass `make test` on its own: when your change
breaks a caller outside your files, make the smallest compiling adaptation
there and list it in your final report.

- **A — `internal/luart`** (new package): everything of sections 1–3, the
  config VM loading of section 4 (init.lua/zel.lua/loads, merge, validation,
  `require("zel")`), hook calls of section 5, `ToolDescription` with
  `lua_main.md`/`lua_headless.md` (short, in the style of
  `internal/core/bash_main.md`), unit tests (`vm_test.go`, `config_test.go`)
  with a fake Env. Do not touch `core`. Go dep: `github.com/yuin/gopher-lua`.
- **B — `internal/config` + `internal/cli`**: section 4 types/connect.json/
  settings parsing/paths/EnsureHome/Watch/Describe, remove YAML + snippets +
  `${{ }}` (drop gopkg.in/yaml.v3), section 7 CLI removals, help text.
  Lua execution is NOT here (luart produces the Config). Keep `core`
  compiling with minimal stubs where needed.
- **C — `internal/tui` + `core/prompts.go` + docs**: section 6, section 8
  (TUI side, trace kind rename in core/trace.go + tui), Lua highlighting;
  rewrite `docs/bash-api.md` as `docs/lua-api.md` (keep `docs.go` topics
  working: tool, api, config, connect, hooks, prompts, colors, examples), new
  `docs/examples/` (init.lua, zel.lua, connect.json, a loads module), README.
