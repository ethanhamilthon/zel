dashy API

Commands, prompts, what goes to the model, TUI commands and config.

CLI

commandwhat it does
dashy [--config FILE]Interactive TUI in the current directory. Needs a terminal. Exits with a setup guide when no provider is configured or, checked in the background, none answers the model listing (same for dashy json).
dashy setupAsks for one provider, API key, model and effort; writes $DASHY_HOME/config.toml.
dashy json [--config FILE]Same session over newline-delimited JSON on stdin/stdout (see below).
dashy models [--json]Prints PROVIDER<TAB>MODEL for every configured provider; failures go to stderr, exit 1. --json prints {models: [{provider, model}], failures: {provider: text}} instead.
dashy tasks run [-s ID] COMMAND...Starts a background task in a running session; the session gets a <task-result> when it ends.
dashy tasks list|status|stop [-s ID] [TASK]List tasks, show one task's state and log, stop a task and its process group.
dashy view [-s ID] PATH...Queues PNG/JPEG images for the next request without blocking the turn (max 4 pending, 32 MiB each).
dashy events [-s ID]Notices and errors the session showed, oldest first.
dashy versionPrints the version.
dashy --help | -h | helpFull reference.

-s ID targets a session; by default helpers use DASHY_ENDPOINT, which the bash tool exports. tasks, view, events, read, grep, write, patch are helpers: they never open a session.

Prompt

The system prompt (instructions) is only the [system.*] blocks, joined in file order with a blank line. text blocks are added as they are; bash blocks run with sh -c in the project (30s limit) and add stdout when they exit 0. Empty results are skipped. With no blocks configured, the prompt is empty.

Blocks written by dashy setup

blocktypevalue
system.maintextYou are Dashy, a coding agent. Keep answers short and precise.
system.agentsbashcat AGENTS.md 2>/dev/null || true (the project's AGENTS.md)

bash tool description (built in, always sent)

You are Dashy, a coding agent. Use the bash tool to help the user. Use `dashy --help` to work with yourself.

Read and search files with standard tools: `cat -n`, `sed -n 'A,Bp'`, `rg` (or `grep -rn`), `ls`, `find`.

To see an image, use `dashy view PATH`.
For long commands (builds, test suites, servers), use background tasks instead of `&`:
- dashy tasks run COMMAND...  starts it; the result arrives as a <task-result> message when it ends
- dashy tasks list | status TASK | stop TASK

LLM request

OpenAI Responses API (or Chat Completions with api = "chat" in the provider, sent to POST {base_url}/chat/completions), streamed over SSE. One request per model step:

POST {base_url}/responses
Authorization: Bearer {api_key}        # only when api_key is set
Content-Type: application/json

{
  "model": "[agent].model",
  "instructions": "joined [system.*] blocks",
  "input": [ ...session history... ],
  "store": false,
  "stream": true,
  "tools": [{
    "type": "function", "name": "bash", "strict": true,
    "description": "<bash tool description, below>",
    "parameters": {
      "type": "object",
      "properties": {
        "command": {"type": "string"},
        "timeout": {"type": ["integer", "null"],
                    "description": "seconds, default 120, maximum 600"}
      },
      "required": ["command", "timeout"],
      "additionalProperties": false
    }
  }],
  "reasoning": {"effort": "[agent].effort", "summary": "auto"}
}
  • reasoning.effort is omitted when effort is empty (default); summary is omitted when reasoning_summary = false; no reasoning key when both are off.
  • The prompt is built once per session and stored in its history; a resumed session keeps it until Reload or New session in the menu.
  • The loop: request → run every function_call in order → next request, until a response has no calls and no steering is waiting.
  • Retries: 3 attempts, backoff 1s, 2s, 4s… capped at 8s (honours Retry-After), only for 408/409/429/5xx, network errors and streams without response.completed, and only if nothing was shown yet.
  • Stream limits: 8 MiB per event, 64 MiB and 100000 events per response. Provider errors are redacted: API keys never reach the screen.
  • Models list: GET {base_url}/models, paginated.

Menu

Ctrl+K opens and closes the menu; arrows or the mouse select, Enter opens, Esc goes back a page.

itemwhat it does
ResumeOpens a saved session of this project.
New sessionStarts a new chat; re-reads all config layers and rebuilds the system prompt.
ModelPick a model, then a reasoning effort. Changes the model of this session and saves it as the default: provider, model and effort are written in place into the config layer each one came from (global if none). Sessions that already have messages keep their model.
TasksPick a background task, then show its output or stop it.
TracingEverything the session did: system prompt, messages, bash calls and their output, reasoning, tasks and client events, searchable and scrollable.
RenameRenames the session (empty restores the default title).
InfoPrints session ID, project, config files, model and token/cache totals into the history (not sent to the model).
ReloadRe-reads the config for the next request; a running turn is not interrupted.
HelpKeyboard shortcuts.
QuitSaves the chat and exits.

Sending while dashy works steers the turn: a running bash call moves to the background as a task and the model reads the message next. While it works, an indicator above the input shows the elapsed time and the step count; the running command is in the Tracing menu. Click a link, or a URL or an existing file path in backticks, to open it.

Config

Layers

defaults→$DASHY_HOME/config.toml→/dashy.toml→…parent dirs…→PROJECT/dashy.toml→--config FILE→model saved with the session
  • Missing files are skipped, except --config, which must exist. Bad TOML or an unknown key is an error.
  • Scalars: a later layer overrides only keys it sets. [ui.events], [ui.theme] and [provider.NAME] merge by key. [system.NAME] and [hooks.NAME] replace an entry with the same name and keep its position; new ones are appended.
  • Nothing can be unset; a hook can be turned off with enabled = false.
  • {{$VAR}} in any string reads the environment. Validation runs once on the merged result.
