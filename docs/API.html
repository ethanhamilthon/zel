Run make install to install ~/.local/bin/zel. First launch opens onboarding inside the application: provider name, base URL, API key, API type (responses or chat), then model and effort. Tab / Shift+Tab switch steps; Left / Right edit text; Enter advances. There is no setup subcommand.

Providers, keys, preferences, defaults, sessions, and tasks live in ~/.zel/zel.db. Keys are stored locally, not encrypted. Override the state directory with ZEL_HOME. Zel does not load or migrate old Dashy data. Manage preferences in Settings and providers in Providers. Model-list failures can be retried or bypassed through manual entry.

Headless mode prints the persisted session ID first, then the final answer and exits. Diagnostics use stderr. Model, provider and effort flags override defaults for this session only. Read committed history with zel session -s ID while running or after exit.

The lua tool and init.lua

Zel 0.5 is a breaking release: the Bash tool and ZEL.md are gone. The model has one tool, lua; its input is raw Lua code. Each Lua invocation has a fixed 30-second timeout that cannot be changed. The session's Lua VM keeps globals and functions between calls until the session changes, init.lua reloads or a call times out; state.get/set/list outlives it. Output is not truncated: filter it in Lua (print(slice(fs.read("big.md"), 100, 10))). Everything blocks except tasks.spawn(fn), which runs a Lua function in its own VM, and agents.spawn; both return a job ID, and finished jobs nobody waited for arrive as <notification>t1 finished</notification>; tasks.* and agents.* each have wait, wait_all, result, status, tail and stop. Agents run inside the application. Full host API, error model and hook table: docs/lua-api.md.

-- ~/.zel/init.lua, then the nearest .zel/init.lua, then --config FILE
local zel = require("zel")
zel.instructions{file = "AGENTS.md"}
zel.prompt(function() return "git: " .. sh("git status --short").out end)
zel.defaults{model = "sonnet-5.5", effort = "medium"}
zel.fn{name = "zel.check", summary = "run tests", params = {{"pkg", "string?", default = "./..."}},
       run = function(pkg) return sh("go test " .. pkg).out end}
zel.on("turn_end", function(ev) end)

Layers are read once per session (and on resume) and form a snapshot; Menu → Reload rebuilds it and the system prompt, after the current turn if one is running. A layer that fails to load is skipped with a notice. Registered functions are rendered into the system prompt.

One accent is used throughout the UI, with neutral shades and red for errors. The default is terracotta. Available colors (Settings):

terracotta, rose, dusty-pink, mauve, lavender, violet, slate, blue, sky, teal, sage, olive, moss, sand, ochre, amber, peach, clay, copper, plum

Hooks

zel.on(event, function(ev, ctx) ... end)
session_start   {}                       return text (or {notify="text"}) to notify the agent
session_end     {reason}                 quit / new / resume; shares the 5 s shutdown budget with running subagents' end hooks
message         {text}                   return a new user text
turn_end        {answer}                 return text (or {notify="text"}) to continue (at most 3 times per turn)
subagent_start  {id,prompt,model,effort,provider,cwd,depth}  runs in the background when a subagent begins; no text to the agent
subagent_end    {id,status,ok,answer,error,session,model,effort,ms}  exactly once per started subagent: done / failed / stopped / timeout; within the 5 s shutdown budget while the session closes

Hooks of all layers run, global first; an error in a hook is logged to Tracing and ignored. Text from session_start and turn_end reaches the agent as a <notification>; message hooks rewrite the user's text; subagent hooks return nothing. The 5 s shutdown budget applies only to lifecycle job and hook shutdown (not database or config preparation/saving before shutdown, or session_start after switching), so contention can make NewSession, Resume, or save-on-quit exceed 5 s. Lua output has only a 1 MiB safety cap; sh().out keeps up to 8 MiB.

Prompt completions: zel.complete(name, fn) registers #name. Typing # in the composer lists the names; Tab or Enter completes the token. Sending a message that names a registered completion runs fn then and sends its returned text instead of the token. Unknown names stay as typed, each name runs once per message, and a failing function keeps the draft. Ctrl+D while it expands cancels the send: nothing is sent and the draft stays.

Ctrl+M and Ctrl+I require Kitty keyboard protocol support; otherwise use Menu. Chat contains only user messages, answers, the working indicator (with the Lua host operation it waits on, such as reading ~/.zel/init.lua; each running subagent row shows its own), and a red closing line for a turn that fails or is stopped (wall-clock time and steps, then the error or "stopped by user"). Tracing shows everything else. Search accepts :user text, :lua text, and all displayed entry types.

Files includes hidden entries, ., and .., with directories first. Enter opens a directory or edits a regular file using the UI editor preference, then VISUAL / EDITOR, defaulting to nvim. The editor hands the terminal back when it exits. Info shows project name, description, color, instruction layers, and token usage.

Security

Commands and hooks run with your user permissions and network access, not in a sandbox. Review unfamiliar project instructions and hooks before launching. API keys may reference environment variables with {{$VARIABLE}}. The full conversation and provider secrets are not explicitly passed to hooks; commands still inherit your shell environment.
