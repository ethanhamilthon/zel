# Performance and Architecture Audit — 2026-11-16

## Scope and method

Audited commit `bb73d4d` on an Apple M1 Pro, macOS, Go 1.27.4. Three read-only reviews used `gemini-4-hydrogen-xhigh` (runtime, TUI, architecture); the coordinating review checked the findings against source and ran independent measurements. No application source or configuration was changed. This document is the only repository addition.

`make test` passed: formatting, vet, and all race-enabled package tests. This establishes the existing tests pass, not that every lifecycle or performance scenario is covered.

The repository has approximately 15,389 production Go lines and 7,581 test lines under `internal/`. `core` and `tui` account for approximately 69% of production lines.

Temporary benchmarks were added to a separate copy at `/tmp/zel-audit-20261116/repro`, not to the repository. Existing benchmark runs and profiles are in `/tmp/zel-audit-20261116/`. Local session data was read without changing or resuming the original sessions. No prompts, image data, credentials, or private session contents are reproduced here.

## Prioritized performance findings

### P1 — Accumulated tool arguments are reparsed for every fragment

**Source:** `internal/core/runtime.go:25-47,449-457`; `internal/provider/freeform.go:95-103`; `internal/tui/queue.go:134-152`; `internal/entities/types.go:96-117`.

Every incoming bash-argument fragment appends an immutable string, then reparses the accumulated JSON to display partial code. Fallback parsing retries multiple suffixes. Each update emits the entire accumulated script as a final provisional event, which the queue cannot coalesce. Total work grows roughly quadratically with command length at fixed fragment size. The actual production parser reproduced ~60 ms and 145 MB of temporary allocations for one ~16 KiB command in small fragments.

Separately, freeform normalization accumulates another complete input string whose content is never read: only key existence matters. This path depends on provider mode and endpoint; the current local Responses proxy does not automatically enable native freeform tools.

**Fix:** replace unread freeform accumulation with a started flag; throttle partial-code previews or decode incrementally; preserve one authoritative argument buffer; make preview coalescing explicit without dropping committed events. Preserve safe handling of split escape sequences and UTF-8.

### P1 — Image-heavy history is repeatedly scanned, and images remain resident

**Source:** `internal/core/runtime.go:425-433,517-548`; `internal/core/system.go:102-118`; `internal/core/steering.go:41`; `internal/core/compaction.go:92-134`; `internal/entities/types.go:127-156`.

The inspected ~17 MiB session contains ~16.5 MiB of user records, dominated by image-bearing inputs. `estimateTokens` unmarshals each JSON item and runs a regex replacement across encoded image payloads merely to count non-image bytes. On this actual history that took ~484 ms. A full count happens when provider-reported context usage is unavailable, including resumed-session/fallback paths; it is **not necessarily run over the full history for every streamed token**.

Compaction changes outgoing requests, not the retained raw history. A separate heap test measured ~17.3 MiB live after loading this history, ~17.5 MiB after repeated processing, and ~17.4 MiB after building a fully compacted request. Reserved heap grew to ~51.6 MiB, but that is neither all live data nor the macOS footprint.

**Fix:** cache immutable per-item token estimates and type/role metadata, sum incrementally, and avoid scanning base64 payloads for a text estimate. For larger savings, keep attachment previews as file-backed references and materialize only for a request. That requires an explicit persistence migration, offline replay guarantees, and tests; do not silently strip images from saved sessions.

### P1 — Full-text Markdown/link processing survives the streaming prefix cache

**Source:** `internal/tui/markdown.go:43-94,190-219,289-327`; `internal/tui/render.go:61-97`.

Glamour's stable prefix is cached, but marker cleanup, plain-path discovery, code-path discovery, hyperlink postprocessing, row wrapping, and painting still traverse the complete changing message. Code/path candidates repeatedly call `os.Stat`, including negative lookups. The measured ~60 KiB frame allocated ~6.89 MB in ~8.25 ms; at a sustained 30 redraws/second that workload would allocate ~207 MB/second, not retain that much each second. The CPU profile showed syscall time as the largest sampled cost for the inline-code workload.

**Fix:** cache path existence per render/session revision (with bounded lifetime), process stable blocks once, and render only changed blocks. A cheaper plain-text preview during streaming is a fallback, but changes appearance. Preserve hyperlinks and final Markdown fidelity.

### P1 — UI drawing bypasses the existing layout throttle

**Source:** `internal/tui/ui.go:231-258`; `internal/tui/ui_events.go:209-218`; `internal/tui/display.go:27-92`.

The ~33 ms throttle limits timeline rebuilding, but every `Update` still invokes `display.draw(n.render(), ...)`, including events that only set `dirty` or do nothing. This repeats viewport rendering and row preparation even when terminal writes are ultimately skipped. This is a proven redundant-work path, not a measured end-to-end slowdown percentage. Shift detection is quadratic in terminal height in the worst case, but identical prepared frames exit its search early; it is not always quadratic.

**Fix:** separate state/layout invalidation from screen invalidation, coalesce redraws, and skip rendering unchanged screens. Keep cursor updates, selection-preserving terminal scrolling, resize behavior, and input latency covered by tests.

### P1 — Controller critical sections include slow external work

**Source:** `internal/core/control_controller.go:42-44,90-98`; `internal/core/control_ops.go:85-118,161-184,220-229`; `internal/core/selection.go:55-73`; `internal/core/settings.go:200-223`; `internal/core/session.go:111-155`.

Reload, model selection, and session switching can execute configuration expressions, synchronous hooks, persistence, or shutdown waits while `Controller.mu` is held. UI reads and event observation also require that mutex. User-configured slow commands can therefore stall the interface or event delivery. This is conditional on external work being slow; no live session was deliberately stalled during the audit.

**Fix:** reserve an operation/state transition under lock, perform external work outside it, then validate the operation/session generation and publish under lock. Do not merely remove the lock. `Controller.Trace` already reads/parses the event-log portion outside the lock; the remaining history extraction inside the lock is the relevant cost.

### P2 — Append-only persistence still prepares the entire history

**Source:** `internal/core/storage.go:131-164`; `internal/store/store.go:178-232`; `internal/agent/agent.go:32-43`; `internal/core/turn.go:78-80,108-110`.

Each Save constructs the full item slice and remarshal of all historical metadata, despite the store only appending the unsaved suffix. `meta.json` is rewritten even when no session bytes changed. Saves occur at multiple safety boundaries, so overhead accumulates with history length. At 10,000 small items, a no-change Save cost ~3.85 ms and 1.69 MB allocated.

**Fix:** serialize only new/dirty metadata and skip genuinely unchanged writes. Cache the first-user summary. Preserve crash recovery and commit-before-tool-execution ordering; deleting safety-boundary saves indiscriminately is not a safe optimization.

### P2 — History upgrade and rebuild work includes offscreen entries

**Source:** `internal/tui/render.go:198-244`; `internal/tui/ui.go:254-258,321-329`.

Initial load or invalidation renders entries newest-first, then repeatedly upgrades drafts with a ~25 ms per-frame budget. Every upgrade rebuilds the combined row index; each changed streaming entry also rebuilds that index over the whole history. Large sessions can therefore keep the UI busy until the backlog clears. Fully warmed idle refresh is inexpensive, as measured above.

**Fix:** prioritize visible rows, make upgrades interruptible in smaller units, and update the row index incrementally. Do not begin with a wholesale virtualized-scrollback rewrite before measuring the simpler changes.

### P2 — Hidden records and caches retain avoidable display data

**Source:** `internal/tui/ui.go:37,49`; `internal/tui/render.go:210-244`; `internal/tui/trace.go:89-119`; `internal/tui/markdown.go:179-187`; `internal/tui/render.go:33-48`.

The UI retains committed tool/reasoning/output records even though chat hides them and the persisted trace can reconstruct them. Raw history and decoded UI strings coexist. The global stable-Markdown prefix cache survives session switching, while the painted-row cache clears wholesale at 8,192 entries. These are retention/churn mechanisms, not proof of an unbounded leak beyond the deliberately growing session history. The painted cache is bounded; describe it as such.

**Fix:** separate chat records, live preview records, and trace snapshots; discard committed hidden previews when safe. Scope/reset caches on session/theme changes and cap expensive caches by byte budget where practical. Keep turn-step statistics and trace navigation intact.

### P2 — Live menus repeatedly reconstruct snapshots

**Source:** `internal/tui/ui_events.go:283-442`; `internal/core/trace.go:27-111`; `internal/core/control_ops.go:220-229`; `internal/core/settings.go:272-285`.

An active Tracing/Info/Resume menu can refresh every 250 ms. Trace extraction reparses history and rereads the log; Info recounts history; Resume lists session metadata files. A 5,000-event trace snapshot allocated ~1.97 MB per refresh. Separately, Settings returns cloned provider/environment maps and is repeatedly fetched from the UI.

**Fix:** use revision-based cached snapshots and incremental trace tails; keep slow reads outside controller locks; expose a small immutable UI/theme snapshot. Keep polling as a fallback where external processes can change state. Polling a few files at 500 ms is not itself a reason to introduce a complex filesystem-watcher subsystem. Deduplicate watch paths (`internal/core/session.go:165-168`).

### P2 — Current Rex status hooks add observable latency outside the repository

**Source:** `internal/core/hooks.go:45-145`; active `~/.zel/zel.toml`; `~/.zel/bin/rex-zel:43-74`.

Across existing local trace logs: `bash_after` had 264 samples, median 127 ms, p95 160 ms; message hooks had 39 samples, median 103 ms; turn-end hooks had 47 samples, median 148 ms. These samples include historical configurations and failures, not a controlled measurement of one current script revision. The configured status helper starts Python and invokes Rex inspection, session lookup, and tab rename commands. It updates the title even on frequent status-only events.

**Fix:** retain main-only lifecycle hooks and only working/done states. Avoid repeated title lookup/rename when the label is unchanged; separate title updates from status signaling; deduplicate unchanged status. Do not disable safety hooks or move rewriting/blocking hooks asynchronously. This local integration cost is distinct from Zel's base memory footprint.

### P2/P3 — Small but concrete lifecycle, adapter, and log-tail cleanup

- **Async hooks:** `internal/core/hooks.go:67-73`; `internal/core/session.go:77-94`. Background hooks use independent contexts; shutdown waits after release/removal of an unsaved session. Add a cancellable lifecycle and a bounded shutdown policy; clean up directories after hooks finish. Reproduce timeout and error paths before changing ordering.
- **Task tails:** `internal/core/jobs.go:154-162` reads the entire log before retaining its tail, although task logs are capped at 8 MiB. Use `ReadAt`/seek for the requested suffix. The old `tasks.go:269-302` already demonstrates bounded reading but is not the production `tailLines` path.
- **Chat adapter:** `internal/provider/chat.go:146-152,206` serializes normalized events to JSON and immediately decodes them again, plus repeatedly concatenates arguments. Construct typed events directly. This is not the current local Responses configuration's main path; verify both protocols.
- **Hook regex:** `internal/core/hooks.go:56-63` recompiles match expressions per invocation. Validate/compile at config-load time; low priority compared with subprocess overhead.
- **File completion:** `internal/tui/files.go:136-166` scans only one directory, not the whole project. Very large directories and symlink-heavy listings remain a conditional cost. Keep the current debounce/cancellation before considering a global index.

Source searches found these APIs have no production callers (some are used by tests):

**Conservative estimate:** approximately **250–350 production lines** removable or consolidatable without deleting supported behavior, subject to implementation and test migration. This is a review estimate, not a measured diff. The subagent's larger ~415–460-line estimate included removing the UI disk spool; that recommendation is not accepted below. Deleting test lines is not itself an optimization target.

### Simplify without introducing new frameworks

1. **One shell execution path.** Tests currently keep an obsolete Runner abstraction alive while production uses Command/Reap plus runtime-specific lifecycle handling. Test the path actually shipped.
2. **One model catalog loading path.** Remove the unused alternate cache before adding more caching layers.
3. **One bounded task-tail reader.** Combine the correct old bounded-read behavior with the current job-facing API, rather than maintaining two implementations.
4. **Explicit lock scopes.** `internal/core/selection.go:55-66` uses deferred unlock/relock ordering around hooks. Replace it with straightforward scoped updates; retain atomic rollback on apply failure.
5. **Deduplicate leaf operations selectively.** Shared path resolution, the original-image marker, and config-expression execution are reasonable candidates. Do not add generic dependency injection or reflection to save a handful of lines.
6. **Fix architecture documentation to describe reality.** `docs/ARCHITECTURE.md:22-24` forbids backend imports from TUI, but `tui/theme.go:9` and `tui/render.go:14` import the pure config package. Either explicitly allow that immutable leaf dependency or consistently expose the necessary UI types. Adding aliases solely to satisfy an arbitrary diagram is not automatically simpler. The document also claims boundary tests that were not found, and describes child chat rows no longer rendered. Add a small import-boundary test only for boundaries the project actually wants to preserve.

## Designs to keep / recommendations rejected after validation

- **Keep agent.Host and the small agent loop.** Its ~71 production lines isolate cancellation and commit-before-execution behavior; inlining it saves little and weakens a useful boundary.
- **Keep immutable session ownership and Controller serialization.** Narrow slow critical sections instead of merging everything into one mutable object.
- **Keep append-only storage and torn-write recovery.** Optimize suffix preparation, not durability semantics.
- **Keep provider normalization, both supported protocols, retry safety, and redaction.** They represent real requirements, not hypothetical extensibility.
- **Keep process-group/lifeline cleanup, bounded shell capture, and stream limits.** Removing these to save code trades correctness for cosmetic simplicity.
- **Do not simply delete the UI queue's disk spool.** `internal/tui/queue.go:16-132` bounds the in-memory event count and preserves committed-event ordering when the UI falls behind; `internal/tui/tui_test.go:2013` explicitly covers this requirement. The architecture reviewer proposed an in-memory-only queue, but without a byte budget/backpressure policy that reintroduces memory growth or event loss. Synchronous spool I/O under the controller callback is a legitimate issue; optimize coalescing or redesign the bounded transport with equivalent guarantees, rather than removing the guarantee.
- **Keep selection-preserving custom display behavior.** It solves a concrete terminal problem. Skip redundant draws before replacing the renderer.
- **Do not call growing session history a proven leak.** Retained images, UI records, caches, transient allocations, Go heap reservation, RSS, and macOS footprint are different quantities. Only direct measurement can attribute a live process's full memory use.
- **Do not optimize startup packaging first.** Importing TUI dependencies for helper commands is conceptually heavy, but the audited version command completed in ~0.01 seconds and an empty TUI used ~13 MB footprint. A second binary/build split would add complexity without a demonstrated bottleneck here.

## Recommended delivery sequence and acceptance checks

### 1. Low-risk cleanup plus baseline coverage

Remove dead model cache/helpers and obsolete shell APIs; consolidate the task tail; simplify lock scopes and correct docs. Preserve cancellation, background adoption, output bounds, and recoverable persistence tests. Run `make test` after each coherent change. Commit behavior fixes separately from dead-code deletion.

### 2. Highest-value allocation and latency fixes

- Bound/throttle partial bash previews and remove unread freeform string accumulation.
- Cache per-item token estimates; avoid repeated base64 scans.
- Cache path checks and stable rendered blocks; skip unchanged draws.
- Measure the existing Rex helpers and remove redundant title/status subprocess calls while preserving main-only lifecycle semantics.

Add narrowly focused benchmarks for long streamed arguments, image-heavy histories, and streaming Markdown. Compare before/after at fixed workload, fragment size, terminal size, and provider mode. Check final text, trace completeness, escaping, and tool execution are unchanged. Allocation reductions here need no architecture rewrite.

### 3. History scaling and lifecycle work

Prepare only dirty persistence items; cache immutable display/trace projections; update row indexes incrementally; move blocking transitions outside Controller.mu with generation checks. Treat file-backed image history as a separate migration. Exercise slow hooks, reload during a turn, cancellation during streaming, session switching, and queued-event spill/drain.

### Suggested performance gates

These are goals to establish and tune, **not promised outcomes**:

- Tool-preview processing should scale approximately linearly with total argument bytes, rather than with the sum of all prefixes.
- Unchanged draws should do no full-frame rendering or filesystem probes.
- Recounting context after appending a small item should not rescan historic images.
- No-change Save should avoid work proportional to total metadata and avoid unnecessary writes.
- Warmed idle timeline refresh should remain cheap at 10,000 entries; separately measure initial render and resize backlog.
- Track live heap and system footprint separately after repeated turns and after session switching. No automatic GOMEMLIMIT/GOGC tuning is recommended before fixing allocation sources.

### Limitations

No production-process heap dump, end-to-end model/network timing, long battery run, extended soak test, or exhaustive fault-injection matrix was captured. This is a repository-wide source review plus targeted local measurements, not a formal proof that every performance or concurrency problem has been found. In particular, it does not claim to explain every byte of the original ~440 MB combined footprint.
